# FNOS 安装与升级

## 选择安装包

- Intel / AMD NAS：`com.fndns.manager_1.0.11_x86.fpk`
- ARM64 NAS：`com.fndns.manager_1.0.11_arm.fpk`

在 FNOS 应用中心选择“手动安装”，上传对应 `.fpk`。应用最低目标版本为 FNOS 1.1.8。

安装完成后，从管理员桌面或应用中心打开“DNS 管理器”。入口被标记为仅管理员可见，请求由 FNOS 统一网关验证系统登录态，不需要应用内再次登录。

## 从旧版升级

已经安装旧版本时，在应用中心使用“手动安装”上传同架构的 1.0.11 包并执行升级。升级会保留 `TRIM_PKGVAR` 中的凭据、缓存和日志。完成后刷新 FNOS 桌面；若浏览器仍缓存旧入口，可退出 FNOS 后重新登录。

如果当前 FNOS 不接受原位升级，可先卸载旧版，并在卸载向导中选择“保留应用数据（推荐）”，再安装 1.0.11。不要选择永久删除数据。

## 首次配置

1. 打开“API 凭据”。
2. 添加 Cloudflare API Token 或腾讯云 DNSPod 密钥。
3. 应用会先验证权限，再把凭据加密写入设备本地。
4. 验证通过后自动同步一次域名列表。
5. 进入域名后，点击“同步记录”拉取该域名的解析记录。

应用此后不会自动刷新。所有同步都由管理员手动触发。

## 数据位置

FNOS 会把运行数据放入应用的 `TRIM_PKGVAR` 目录，其中包括：

- `data/master.key`：AES-256 主密钥，权限为 `0600`
- `data/fndns.db`：凭据密文、域名/记录缓存与操作日志
- `fndns.log`：服务运行日志
- `fndns.pid`：运行时 PID

升级不会删除这些数据。

## 卸载

卸载向导会询问：

- 保留应用数据：重新安装后可继续使用原有凭据和缓存
- 永久删除应用数据：删除凭据、主密钥、缓存和日志，无法恢复

如果删除了 `master.key` 但保留数据库，原凭据密文也无法解密。

## 故障排查

- 应用无法启动：查看 FNOS 应用日志和应用数据目录中的 `fndns.log`
- 凭据验证失败：检查权限、设备时间、Secret 是否完整，以及 NAS 是否能访问对应平台 API
- 数据与控制台不一致：点击单域名“同步记录”；应用不会自动刷新
- 提示远端冲突：说明记录被其他工具修改，先手动同步再重试
- 缓存已过期：缓存仍可查看，但必须同步后才能修改
